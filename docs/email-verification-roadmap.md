# 邮件验证：后续版本

2026-09-24 发布范围调整：团队尚无可验证的发件域名，因此本次保持用户名、邮箱和密码直接注册。服务端保存密码哈希并签发 HttpOnly 会话，注册不依赖邮件服务；登录限流、账号隔离与后台生成继续发布。

当前邮箱仅为用户填写的未验证信息，不作为邮箱所有权证明，也不能直接用于密码重置或账号合并。现有账号和数据保留。

下一版接入前需要：

1. 准备团队拥有且可管理 DNS 的域名，在邮件服务中完成发件域名验证。
2. 配置服务端发件密钥、发件邮箱和公开站点根地址，并验证真实邮件送达。
3. 给现有和新账号明确记录邮箱验证状态，设计已有未验证邮箱的处理与迁移流程，避免冒领账号。
4. 恢复并完善一次性验证链接、过期、重发、失败清理和限流，验证链接不得出现在日志中。
5. 验证注册、登录、重发、过期链接、重复提交和多设备流程后再发布。

队友的邮件验证原实现保存在 Git 提交 `33abc7ebeac2599d1741f94452e4bf9ed064cce3`，可作为后续实现参考；不要直接启用未经配置的版本。
