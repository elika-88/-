# 生成额度与用量账本：后端交接

负责人：elika-88；前端额度展示接入：xiaomao。当前实现为 Beta 使用次数管理，不是支付、订阅或供应商费用结算系统。

## 本次规则

- 每账号每 UTC 自然月默认 60 次；一份符合现有输入上限的学习材料计 1 次，不按题目数或模型调用数收费。
- 新任务入库与额度预留在同一个数据库写事务中完成。成功结果保存与扣除也在同一个事务中完成。
- 最终失败、取消、排队超时、执行器重试耗尽返还额度。自动重试复用原预留；手动重试创建新任务并重新预留。
- 成功后结果另存副本、或课程已删除但结果仍能从任务中获取，也算成功并扣 1 次。
- 取消执行中的任务立即返还用户额度，但在 worker 确认或租约到期前仍保留原并发锁。取消不代表供应商费用被退回。
- 跨月任务按提交时的月份结算；新月自动使用新额度，无需定时充值。所有日期为 UTC，接口时间戳单位为毫秒。
- 全站每日新任务上限默认 500 次，按 UTC 自然日计算。失败/取消不恢复全站次数，避免失败重试无限消耗资源。原有每小时/滚动24小时/并发上限也继续生效，取更严格的限制。

## Vercel 配置

在项目 Settings → Environment Variables 中设置并在新部署后生效。全部为服务端变量，不带 `NEXT_PUBLIC_`。

| 变量 | 默认值 | 含义 |
| --- | --- | --- |
| `LUMINA_MONTHLY_GENERATION_LIMIT` | `60` | 每账号每月额度，设 `0` 禁止新的额度预留 |
| `LUMINA_GLOBAL_DAILY_GENERATION_LIMIT` | `500` | 全站每天新任务数，包含最终失败与取消 |
| `LUMINA_GENERATION_PAUSED` | `false` | `true` 暂停接受新任务和领取排队任务；已执行的调用可能继续完成 |

整数范围为 0–1,000,000；非法值返回 `503 USAGE_CONFIG`，不会默认为无限额度。降低额度不撤回已预留任务或历史材料；剩余额度最低为 0。

仍需此前已配置的 Turso、Inngest 和 AI 服务端配置，尤其是 `LUMINA_BACKGROUND_GENERATION=true` 及恢复函数正常运行。暂停新生成时保留 Inngest 恢复函数运行，以释放过期任务的预留；不要用关闭所有恢复任务来暂停生成。

## API：给 xiaomao

`GET /api/usage` 携带登录 Cookie 和 `X-Lumina-Account: <当前 user.id>`。不要从 query/body 指定另一个账号。共享 Zod 契约在 `lib/contracts/usage.ts`，响应设置 `Cache-Control: no-store`。

```json
{
  "userId": "当前账号 UUID",
  "plan": "beta",
  "unit": "study_kit",
  "period": { "start": 1788220800000, "end": 1790812800000 },
  "limit": 60,
  "used": 12,
  "reserved": 1,
  "remaining": 47,
  "generationPaused": false
}
```

前端建议显示“本月剩余 47 次 · 1 次生成中”，成功/失败/取消后重新查询，不自行增减本地余额。返回值是查询时的快照，提交接口仍是最终判断。账号切换时取消旧请求并清空旧余额。未登录不查余额；401 回到登录，409 `ACCOUNT_CHANGED` 重新确认账号，503 保留已显示内容但提示无法获取最新额度，不能伪造 0 或无限次。

提交和重试的成功返回仍兼容现有后台任务接口，新的错误沿用 `{ "code": "...", "error": "..." }`：

| 状态/错误码 | 前端处理 |
| --- | --- |
| 429 `QUOTA_EXCEEDED` | 展示额度用完或已预留；刷新余额，不自动循环重试 |
| 429 `DAILY_CAPACITY` | 当日全站次数已满，UTC 次日再试 |
| 503 `GENERATION_PAUSED` | 显示暂时停用，继续允许阅读和导出历史 |
| 503 `USAGE_CONFIG` / `UNAVAILABLE` | 服务不可用，失败时不绕过额度 |
| 409 `REQUEST_EXPIRED` | 原任务结果已清理；明确再次生成时创建新请求键 |
| 409 `IDEMPOTENCY_CONFLICT` | 相同请求键用于不同课程/版本，修正客户端请求键管理 |

同一提交因网络断开重试时必须复用同一个请求键。正在生成的同课程同版本提交会映射到同一任务；每个任务最多保存 32 个请求键，超过返回 429，不允许无限制造别名。

生产和 Vercel Preview 的 `POST /api/generate` 不再调用模型：访客返回 401 `LOGIN_REQUIRED`，已登录返回 409 `BACKGROUND_REQUIRED`。旧接口保留原有 `{error:{code,message,retryable}}` 结构。访客可保留本机材料、导入课程；生成需登录，然后通过现有“Import guest lectures”主动迁入课程。错误旁已增加登录链接，不自动迁入访客资料。本地 development/test 可继续使用流式接口调试，这些调用不纳入生产额度。

## 数据库和升级

表由现有数据库连接自动初始化，不需要新数据库或额外服务：

- `usage_reservations`：每 jobId 一个预留，带 userId、原始月份、reserved/charged/released 状态。
- `usage_ledger`：不可变的 reserve、charge、release 事件；`(job_id,event)` 唯一。
- `generation_request_keys`：请求键到任务的映射，防止结果保留期结束后重放旧提交再次扣除。

以上记录不保存讲稿、模型输出、API key 或密码。当前随账号存续保留，任务的 30 天结果清理不删除账本和请求映射。后续账号删除必须包含这些表（现有外键支持级联删除账号所属记录）。

上线前已经创建的任务不补扣，也不追溯历史消耗；它们没有新预留记录，仍能完成或取消。新部署创建的任务全部原子预留。部署期间旧实例仍可能创建不计额任务，因此正式收费前需停流量、完成实例切换再恢复；此版本为 Beta，不声明付费账务保证。

## 验收与边界

自动化回归覆盖并发最后一个额度、重复提交/别名/回调、事务回滚、取消后迟到结果、自动/手动重试、排队和租约超时、UTC 跨月与跨日、清理后账本保留、跨账号查询、旧生产接口绕过与数据库失败。使用本地隔离 SQLite，不调用收费模型。

上线验收：登录后查询余额 → 提交任务看到 reserved 增加 → 成功后 used 增加 → 取消另一任务确认返还 → 在 Inngest 确认恢复函数运行。真实 Turso 并发和供应商生成仍需生产/预发布环境验收。

本任务不声称已完成美元成本监控：次数不是费用。供应商每次调用的输入/输出/cache tokens、失败调用费用、价格版本及预算金额硬上限属于后续独立任务。文件提取限流、私有对象存储上传、支付和反批量注册也仍是发布清单中的后续事项。
